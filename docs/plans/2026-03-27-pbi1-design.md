# PBI ID:1 システム処理フローの作成 - 設計書

## 概要

処理フロー概念設計（`docs/archtecture/overallflow_concept.md`）に基づき、AIチェックのシステム処理フローを実装するための設計。

## アーキテクチャ方針

**アプローチA: 単一Workflow**を採用。

- Step 0（事前処理）/ Step 3（コメント投稿）: アプリケーション層で実行（Gateway経由）
- Step 1（チェックリスト分割）/ Step 2（レビュー実行）: Mastra Workflowで実行
- PBIの方針「1,2についてはmastra workflowで実装する」に準拠

```
[Step 0: 事前処理（App層）]
  → Workflow開始
    → Step 1: チェックリスト分割
    → ForEach: Step 2 レビュー実行（並列度5）
  → Workflow完了
→ [Step 3: コメント投稿（App層）]
```

## ドメイン層

### エンティティ・値オブジェクト

```
domain/
  checkItem/
    CheckItem.ts           # チェック項目（エンティティ）
  reviewResult/
    ReviewResult.ts        # レビュー結果（エンティティ）
  rating/
    Rating.ts              # 評定（値オブジェクト）- label + definition
  reviewSettings/
    ReviewSettings.ts      # レビュー設定（値オブジェクト）
  checklist/
    Checklist.ts           # チェックリスト（エンティティ、CheckItem[]を保持）
  mrContext/
    MrContext.ts           # MRコンテキスト（値オブジェクト）
  priorReviewContext/
    PriorReviewContext.ts  # 前回チェック結果コンテキスト（値オブジェクト）
```

### CheckItem

- `content: string` - チェック項目の本文

### ReviewResult

- `checkItem: CheckItem` - 対象チェック項目
- `comment: string` - AIが生成したコメント
- `rating: Rating` - 評定
- `isError: boolean` - エラーかどうか
- `errorMessage?: string` - エラー時のメッセージ

### Rating（値オブジェクト）

- `label: string` - ラベル（例: "A"）
- `definition: string` - ラベル定義（例: "チェック項目の要件を完全に満たしている"）

ReviewSettingsの評定基準定義とReviewResultの評定結果の両方で同じ値オブジェクトを使用する。

### ReviewSettings（全フィールド任意、デフォルト値あり）

- `additionalInstructions: string` - 追加指示（デフォルト: 空文字）
- `concurrentReviewCount: number` - 同時レビュー項目数（デフォルト: 1）
- `commentFormat: string` - コメントフォーマット（デフォルト: 定義済みテンプレート）
- `ratings: Rating[]` - 評定基準（デフォルト: A/B/Cの3段階）

### Checklist

- `items: CheckItem[]` - チェック項目一覧
- `splitByCount(count: number): CheckItem[][]` - 機械的分割メソッド

### MrContext

- `title: string`
- `description: string`
- `sourceBranch: string`
- `targetBranch: string`
- `diff: string` - MR全体diff
- `commitHash: string` - 最新コミットハッシュ

### PriorReviewContext

- `results: ReviewResult[]` - 前回のレビュー結果
- `commitMessages: string[]` - 前回以降のコミットメッセージ一覧
- `diffSincePrior: string` - 前回以降のdiff

## アプリケーション層

### ポート（Gateway IF）

```
application/
  shared/
    port/
      gateway/
        MrGateway.ts          # MR情報の取得
        MrCommentGateway.ts   # MRコメントの取得・投稿
```

**MrGateway**

- `getMrContext(projectId: string, mrIid: string): Promise<MrContext>`

**MrCommentGateway**

- `getComments(projectId: string, mrIid: string): Promise<MrComment[]>`
- `postComment(projectId: string, mrIid: string, body: string): Promise<void>`

### アプリケーションサービス

```
application/
  executeReview/
    ExecuteReviewService.ts    # メインのユースケース
    ExecuteReviewCommand.ts    # 入力DTO
    ExecuteReviewDto.ts        # 出力DTO
```

**ExecuteReviewCommand（入力）**

- `userId: string`
- `projectId: string`
- `mrIid: string`
- `checklist: Checklist`
- `reviewSettings: ReviewSettings`
- `skillsPaths: string[]`
- `aiApiKey: string`
- `aiApiEndpointUrl: string`
- `aiModelName: string`
- `gitlabToken: string`

**ExecuteReviewDto（出力）**

- `results: ReviewResult[]`
- `commitHash: string`
- `commentPosted: boolean`

**ExecuteReviewService.execute(command) のフロー:**

1. **Step 0**: 事前処理
   - `MrGateway.getMrContext()` でMRコンテキスト取得
   - `MrCommentGateway.getComments()` でコメント一覧取得
   - マーカー付きコメントをパースして最新チェック結果を抽出
     - 今回のチェックリストに含まれない項目の結果は除外
   - 最新チェック結果が存在する場合:
     - その時点以降のコミットメッセージ一覧を取得
     - その時点から現在までのdiffを取得
     - PriorReviewContext を生成
2. **Step 1-2**: Mastra Workflow実行（チェックリスト分割 → レビュー実行）
3. **Step 3**: レビュー結果をMarkdown表に整形し、`MrCommentGateway.postComment()` でコメント投稿

## Mastra Workflow（Step 1-2）

### ファイル構成

```
mastra/
  workflows/
    reviewWorkflow.ts              # ワークフロー定義（stepを組み立て）
    steps/
      checklistSplitStep.ts        # Step 1: チェックリスト分割
      reviewExecutionStep.ts       # Step 2: レビュー実行（forEach）
  agents/
    checklistSplitAgent.ts         # チェックリスト分割Agent
    reviewAgent.ts                 # レビュー実行Agent
  tools/
    storeReviewResult.ts           # レビュー結果格納tool（排他制御付き）
    getReviewResults.ts            # レビュー結果一覧取得tool
```

### Step 1: チェックリスト分割

**入力:** `checklist: CheckItem[]`, `concurrentReviewCount: number`

**ロジック分岐:**

- `concurrentReviewCount === 1` → 各項目を個別グループに（AI不要）
- `concurrentReviewCount >= 総項目数` → 全項目を1グループに（AI不要）
- それ以外 → AI分割を試行

**AI分割の流れ:**

1. チェックリスト分割Agentに全チェック項目を渡し、類似項目のグルーピングを依頼
2. Agentの出力を構造化データとして取得（structured output）
3. 出力結果を検証（項目の過不足、グループサイズ）
4. 不整合がある場合は **AIのグルーピング結果をベースに** 機械的調整:
   - 漏れた項目 → 最もサイズが小さいグループに追加
   - 重複した項目 → 2つ目以降を除去
   - `concurrentReviewCount` を超えるグループ → グループ内で分割し、溢れた項目をプールに退避
   - `concurrentReviewCount` 未満のグループ → プールから補充
   - プールに残りがあれば、サイズが小さいグループに順に分配
   - 最終的に `concurrentReviewCount` ちょうどのグループ + 端数1グループ（最後のみ）を保証
5. Agent処理が完全に失敗した場合のみ `Checklist.splitByCount()` でゼロからの機械的分割

**出力:** `groups: CheckItem[][]`

### Step 2: レビュー実行（ForEach × 並列度5）

**各グループごとの処理:**

1. Workspace付きレビューAgentを生成
   - `LocalFilesystem` + `LocalSandbox`（basePath: `CI_PROJECT_DIR`）
   - デフォルトskills + ユーザ指定skillsをマージ
   - `storeReviewResult` / `getReviewResults` toolを付与
   - モデルは `createOpenAICompatible` でuserIdベースで動的生成
2. Agentにプロンプトを与えて実行:
   - **system**: レビュー方針、全チェック項目、コメントフォーマット、評定基準、追加指示
   - **user**: MR情報、MR全体diff、前回結果+差分（存在する場合）
3. Agent実行完了後、`getReviewResults` で結果を確認
4. 漏れがあればAgentに残りの項目のレビューを指示（メッセージ履歴を保持）
5. 全項目のレビュー結果が揃うまで繰り返し

**レビュー結果格納の排他制御:**

- `storeReviewResult` tool内でファイルロック（mutex）を使用
- 全Agentが同一のjsonファイルに書き込む

### Gateway実装

```
infrastructure/
  adapter/
    gateway/
      GitLabMrGateway.ts          # MrGateway実装
      GitLabMrCommentGateway.ts   # MrCommentGateway実装
```

**GitLabApiClient**

- `/merge_requests/:iid/notes` - ノート一覧取得・投稿
- マーカー付きコメントのフィルタリング・パースはアプリケーション層の責務

## プレゼンテーション層

### src/index.ts のフロー

1. CLIオプション解析（既存の `cli.ts`）
2. Logger初期化（既存の `logger.ts`）
3. 入力ファイル読み込み
   - チェックリストCSVパース → Checklist生成
   - レビュー設定JSONパース → ReviewSettings生成（ファイル未指定時はデフォルト値）
4. `ExecuteReviewService.execute(command)` 呼び出し
   - try-catchで全エラー補足
   - エラー時: エラーメッセージ表示（verbose-errorならスタックトレースも）→ 異常終了
5. 正常終了

### 入力ファイル形式

**チェックリストCSV:**

- 1カラム、ヘッダなし
- 各行が1つのチェック項目

**レビュー設定JSON:**

```json
{
  "additionalInstructions": "セキュリティ観点を重視してレビューしてください",
  "concurrentReviewCount": 3,
  "commentFormat": "## 指摘内容\n{comment}\n## 改善案\n{suggestion}",
  "ratings": [
    { "label": "A", "definition": "チェック項目の要件を完全に満たしている" },
    { "label": "B", "definition": "概ね満たしているが軽微な指摘がある" },
    { "label": "C", "definition": "要件を満たしていない" }
  ]
}
```

- 全フィールド任意。未指定時はデフォルト値を適用
- Zodでバリデーション

## コメント投稿フォーマット（Step 3）

### マーカー構造

```markdown
<!-- aikata-review -->
<!-- aikata-review-data: {"ratings":[{"label":"A","definition":"..."},...], "commitHash":"abc1234"} -->

| チェック項目 | 評定 | コメント |
|---|---|---|
| チェック項目1の本文 | A | コメント内容... |
| チェック項目2の本文 | エラー | エラーメッセージ... |

最新コミット: abc1234
```

### 15項目超の場合

```markdown
<!-- aikata-review -->
<!-- aikata-review-data: {...} -->

<details>
<summary>チェック結果（20項目）</summary>

| チェック項目 | 評定 | コメント |
|---|---|---|
| ... |

</details>

最新コミット: abc1234
```

### マーカーの役割

- `<!-- aikata-review -->` - 本ツールのコメントであることを識別
- `<!-- aikata-review-data: {...} -->` - 評定基準（ラベル+定義）、コミットハッシュ等のメタデータを不可視で保持
- 前回結果取得時（Step 0）にパースしてPriorReviewContextを復元
